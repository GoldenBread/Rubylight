# Wireless burst pacing
- **Steadier Wi-Fi burst pacing through transient RTT spikes.** On wireless clients without a reported link speed, automatic burst pacing no longer steps down to 2x bitrate on quiet scenes, ordinary Wi-Fi jitter, or the multi-second ENet smoothed-RTT decay after a single brief spike (#162). Queue-delay backoff now uses a 30-second rolling RTT floor, requires active traffic with RTT more than 15 ms above that floor for 2 seconds without draining, keeps the RTT baseline across bitrate changes on the same route, and recovers automatically after a lasting shift in route latency. The host's ENet control link also rounds up smoothed RTT updates so reported RTT converges back to actual latency after a spike instead of stalling up to 7 ms high.
