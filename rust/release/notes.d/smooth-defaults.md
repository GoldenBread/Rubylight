# Steadier defaults
- **A game that sets its own display mode no longer stutters every few seconds.** A game in exclusive fullscreen can switch the stream's virtual display from the fast mode Rubylight gives it to its own, often the stream's rate. Rubylight's automatic frame limit then ran at the same rate as the display, and each time the two drifted across each other every other frame was shown twice for a second or two. The automatic limit now switches off whenever the stream's display refreshes at less than one and a half times the limit, so the display's own refresh paces the game, and comes back when the display is fast again. A limit you asked for with "Limit every stream" stays. The host log says when the display changes its refresh rate.
- **Lost packets in a menu no longer halve the bitrate.** Rubylight lowers the bitrate when frames are lost that error correction cannot repair. A menu or a calm scene sends a fraction of the stream's bitrate, so loss there is not the bitrate's doing, yet the bitrate was halved, met the game when the picture moved again and climbed back in steps. Such a cut is now held back while it would not lower what is sent. Loss that goes on, and loss around a large frame, still lower the bitrate.
- **Congestion control no longer collapses the bitrate on a clean link.** With "Congestion control" on, a still picture, a menu or a light scene sends far less than the stream's bitrate. A moment of Wi-Fi jitter was then read as a full link, the bitrate was cut to what that light picture needed, and it could take up to 30 seconds to return when the picture got busy. A stream that sends far below its rate is now cut only when a queue stands on the link. The setting stays off by default.
- **Error correction stays at its percentage.** "Adapt error correction" is now off unless you turn it on. It lowered error correction to 5 % on a link that reported no loss, which sent less data but never raised the picture's bitrate, and the first packets lost after a quiet stretch then cost a frame more easily. Its description now says so.
- **A send-buffer entry at stream start is explained.** Help & diagnostics now says that a single "The network adapter dropped packets" entry from the moment a stream starts costs only the first picture, and that entries which keep coming during play are the ones to fix.
