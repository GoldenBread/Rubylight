# Logs and capture
- **The host's log comes back after a rotation that could not reopen it.** When the log had been moved aside but the new file could not be opened, writing went on in the moved file and the log itself stayed missing; the next line now opens it again. No line is lost.
- **A host log deleted or moved away while the host runs comes back.** Writing used to go on into the deleted file until the host restarted; the log now opens again with the next line written once ten seconds have passed. Lines written in between went into the deleted file and are lost.
- **A host log that cannot be opened again stays within its size limit.** While its file cannot be opened, logging goes on in the older files, which roll over as the log does instead of one of them growing without bound.
- **The host's log copes with its folder being deleted and never grows past twice its size limit.** When the log's folder is deleted while the host runs, the folder and the log are made again in the same way. A log that cannot be rotated at all (another program holding it, a folder in the way) is cut back at twice its size limit instead of growing, which drops the lines in that file; the log then says so in a line of its own, with how much was removed.
- **The `compute_queue_realtime` setting now reaches the Windows Graphics Capture helper.** With capture through its helper process the setting did nothing; the helper is now told and asks for the same real-time GPU priority. Nothing changes while it is off.
